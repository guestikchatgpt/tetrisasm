# Tetris ASM

Классический терминальный Tetris, написанный **целиком на ассемблере x86-64** для Linux.

Главная цель репозитория — не минимальный размер и не максимальная производительность, а понятность для человека, который раньше не писал на ассемблере. Поэтому исходники намеренно содержат очень много комментариев: от устройства `_start` и регистров syscall ABI до collision detection и удаления заполненных линий.

## Что здесь принципиально отсутствует

- C / C++ / Rust и любой другой язык для runtime-части игры;
- libc;
- ncurses;
- SDL;
- звуковая библиотека;
- динамические зависимости.

Игра общается с Linux напрямую через `syscall`: `read`, `write`, `ioctl`, `fcntl`, `clock_gettime`, `nanosleep`, `exit`.

Сборочные файлы (`Makefile` и GitHub Actions YAML), разумеется, не являются частью игрового бинарника.

## Управление

- `←` — влево;
- `→` — вправо;
- `↓` — мягкое падение (+1 очко за клетку);
- `↑` — поворот по часовой стрелке;
- `Space` — жёсткое падение (+2 очка за клетку);
- `Q` — корректно выйти и восстановить настройки терминала.

После Game Over `Space` начинает новую игру.

## Правила

Поле — классические 10×20 клеток, семь тетромино I/O/T/S/Z/J/L, следующая фигура показывается заранее.

Очки за линии:

- 1 линия: `100 × level`;
- 2 линии: `300 × level`;
- 3 линии: `500 × level`;
- 4 линии: `800 × level`.

Уровень повышается каждые 10 очищенных линий. С каждым уровнем автоматическое падение ускоряется, вплоть до минимального интервала 100 мс.

Для простоты и прозрачности исходника здесь нет modern SRS wall kicks и lock delay: поворот либо полностью допустим в текущей позиции, либо не выполняется; если фигура больше не может двигаться вниз, она фиксируется сразу.

## Сборка локально

Нужны GNU binutils (`as`, `ld`) и `make`:

```bash
make
./build/tetris
```

Проверка игровой логики без интерактивного терминала:

```bash
make check
```

Этот режим запускает встроенный `--self-test`, тоже написанный на ассемблере.

## Что происходит при сборке

```text
tetris.s + src/*.inc
      |
      |  as --64
      v
build/tetris.o
      |
      |  ld -m elf_x86_64
      v
build/tetris
```

Здесь нет стадии компиляции языка высокого уровня. Assembler переводит мнемоники (`mov`, `cmp`, `jmp`, `syscall`...) в машинные opcodes, а linker раскладывает секции и адреса в итоговый ELF.

## GitHub Actions

Workflow `.github/workflows/build.yml` на каждом push/PR:

1. собирает программу;
2. запускает assembly self-test;
3. проверяет ELF через `file` и `readelf`;
4. проверяет отсутствие динамических библиотек;
5. публикует готовый `tetris-linux-x86_64` как Actions Artifact.

## С чего читать код

Идите по цепочке:

```text
_start
  -> setup_terminal
  -> seed_rng
  -> init_game
  -> main_loop
       -> poll_input
       -> gravity_step
       -> render
       -> nanosleep
```

Игровая механика:

```text
клавиша / gravity
  -> can_place
  -> move / rotate / drop
  -> lock_piece
  -> clear_lines
  -> spawn_next
```

Подробная карта находится в `docs/HOW_IT_WORKS_RU.md`.

## Если терминал остался в странном режиме

При штатном выходе через `Q` игра сама возвращает `termios`. Но если процесс убить извне (`kill -9` и т. п.), cleanup выполнить невозможно. Тогда обычно достаточно:

```bash
stty sane
```
